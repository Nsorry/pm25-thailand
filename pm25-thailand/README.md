# PhraeBreathe PHEOC

แดชบอร์ดคุณภาพอากาศจังหวัดแพร่ แสดงข้อมูลจากแหล่งข้อมูลที่เชื่อมต่อจริง และเว้นข้อมูลที่ยังไม่มีแหล่งยืนยันไว้เป็น “ไม่มีข้อมูล”

## แหล่งข้อมูล

- **PCD Air4Thai**: ค่าฝุ่นจากสถานี 69t อุตุนิยมวิทยาจังหวัดแพร่ เมื่อสถานีพร้อมให้บริการ โดยเรียกผ่าน local server เพื่อหลีกเลี่ยงข้อจำกัด CORS
- **Open-Meteo Air Quality และ Forecast API**: ค่าฝุ่นและพยากรณ์แบบจำลอง ณ พิกัดอำเภอ ไม่ใช่ค่าจากสถานีตรวจวัดภาคพื้นดิน
- **Open-Meteo Forecast API**: สภาพอากาศ ณ พิกัดเดียวกัน
- **กรมอนามัย**: ทะเบียนสถานที่ห้องปลอดฝุ่น ผลประเมิน และวันหมดอายุใบรับรอง ดึงจากชุดข้อมูลสาธารณะและกรองจังหวัดแพร่
- **สำนักงานจังหวัดแพร่**: จำนวนผู้สูงอายุพิการที่จดทะเบียน รายอำเภอ (แสดงปีข้อมูลจากไฟล์ต้นทาง)
- **สำนักงานสถิติแห่งชาติ / กรมการปกครอง**: จำนวนประชากรอายุ 60 ปีขึ้นไปจังหวัดแพร่ ปีล่าสุดที่เผยแพร่
- **สำนักงานสาธารณสุขจังหวัดแพร่**: จำนวนเตียงรายอำเภอและสถิติผู้ป่วยจากมลพิษทางอากาศรายปีจาก Phrae Government Data Catalog พร้อมปีข้อมูลและลิงก์ต้นทาง
- **OpenStreetMap**: พิกัดศูนย์กลางเขตอำเภอโดยประมาณและแผนที่

ข้อมูลห้องปลอดฝุ่นเป็นทะเบียนสถานที่ ไม่ได้ยืนยันว่าเปิดให้บริการในขณะนี้ ระบบคำนวณสถานะใบรับรองจากวันหมดอายุที่แหล่งข้อมูลระบุ และไม่อนุมานจำนวนผู้ใช้บริการ ความจุ หรือความครอบคลุม หากแหล่งข้อมูลไม่พร้อม ระบบจะแสดงว่าไม่สามารถดึงข้อมูลได้แทนการสร้างค่าทดแทน

## ข้อมูลที่ยังไม่เชื่อมต่อ

ชุดข้อมูลสาธารณะของ สสจ.แพร่ให้จำนวนเตียงรายปี (ปีข้อมูล 2567) และสถิติผู้ป่วยจากมลพิษทางอากาศรายปี (ปีข้อมูลล่าสุดที่มีในไฟล์) แต่ไม่ใช่สถานการณ์ปฏิบัติการปัจจุบัน ไม่พบข้อมูลสาธารณะที่เชื่อมต่อได้สำหรับจำนวนเตียงว่าง/อัตราครองเตียงปัจจุบัน สถิติ OPD รายวัน ระบบนัดหมายหรือเทเลเฮลธ์ สต็อกหน้ากากและเครื่องฟอกอากาศ การเยี่ยมบ้าน หรือความครอบคลุมห้องปลอดฝุ่น ข้อมูลเหล่านี้ต้องใช้ API/ไฟล์สรุปจากหน่วยงานที่ได้รับอนุญาต และจะแสดงว่าไม่มีข้อมูลจนกว่าจะเชื่อมต่อแหล่งดังกล่าว

ข้อมูลบริการและคำขอในแท็บบริการเป็นรายการที่ผู้ใช้บันทึกในเครื่องนี้ ไม่ใช่ข้อมูลปฏิบัติการจากหน่วยงาน

รายการบริการและคำขอที่ผู้ใช้บันทึกจะถูกเก็บในไฟล์ JSON ภายในเครื่องนี้เท่านั้น ไม่ได้เชื่อมต่อฐานข้อมูลของหน่วยงานหรือส่งคำขอให้เจ้าหน้าที่ คำขอใหม่จะส่งแจ้งเตือนผ่าน LINE เฉพาะเมื่อตั้งค่า LINE Messaging API ตามขั้นตอนด้านล่าง

## ตั้งค่าแจ้งเตือน LINE

ระบบส่งคำขอใหม่ผ่าน LINE Messaging API ไปยังผู้ใช้หรือกลุ่มที่กำหนด โดยต้องมี LINE Official Account ที่เปิดใช้ Messaging API, Channel access token และ recipient ID ของผู้ใช้/กลุ่ม/ห้องที่เพิ่มบัญชี LINE ดังกล่าวไว้แล้ว การหา recipient ID ของกลุ่มมักต้องอ่านจาก webhook event ของ LINE; แอปนี้ไม่ได้เปิด endpoint รับ webhook ให้โดยอัตโนมัติ

ตั้งค่าตัวแปรใน PowerShell ก่อนเริ่มเซิร์ฟเวอร์ (แทนค่าตัวอย่างด้วยข้อมูลจาก LINE Developers Console):

```powershell
$env:LINE_CHANNEL_ACCESS_TOKEN = "<channel-access-token>"
$env:LINE_RECIPIENT_ID = "<LINE-user-group-or-room-id>"
npm start
```

ค่าดังกล่าวอยู่ใน environment ของหน้าต่าง PowerShell ปัจจุบันเท่านั้น อย่าใส่ token ลงใน source code, README, `data/` หรือ commit เข้าระบบควบคุมเวอร์ชัน หากเซิร์ฟเวอร์ทำงานอยู่แล้ว ให้หยุดและเริ่มใหม่หลังตั้งค่าตัวแปร

ตรวจสถานะการตั้งค่าได้ที่ `GET /api/v1/line/status` ซึ่งส่งกลับเฉพาะค่า true/false ไม่เปิดเผย secret เมื่อผู้ใช้ส่งคำขอ ระบบจะบันทึกลงไฟล์ในเครื่องก่อน แล้วจึงส่งข้อความ LINE; หากยังไม่ได้ตั้งค่าหรือ LINE ตอบกลับผิดพลาด คำขอยังคงถูกบันทึกและหน้าเว็บจะแจ้งผลตามจริง ข้อความแจ้งเตือนประกอบด้วยรายละเอียดคำขอ ชื่อ และเบอร์โทร จึงควรตั้ง recipient เป็นผู้รับที่ได้รับอนุญาตและแจ้งผู้ส่งก่อนส่งข้อมูล

## เริ่มใช้งาน

ต้องติดตั้ง Node.js ที่รองรับ `--use-system-ca` จากนั้นเปิด Terminal ในโฟลเดอร์โครงการและรัน:

```powershell
npm start
```

หรือเปิด `start.bat` แล้วเข้า `http://localhost:3000`

เซิร์ฟเวอร์ให้บริการข้อมูลผ่าน:

- `GET /api/v1/air-quality/pcd` — ข้อมูลสถานี PCD Air4Thai
- `GET /api/v1/public/health-dashboard` — ทะเบียนห้องปลอดฝุ่น ข้อมูลประชากรผู้สูงอายุ จำนวนเตียงรายปี และสถิติผู้ป่วยจากมลพิษทางอากาศจากชุดข้อมูลสาธารณะ
- `GET /api/v1/line/status` — สถานะการตั้งค่า LINE โดยไม่เปิดเผย credentials
- `/api/v1/services` และ `/api/v1/requests` — รายการบันทึกในเครื่องนี้
